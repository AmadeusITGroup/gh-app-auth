## C1: system context

Who uses gh-app-auth and what it talks to.

<ContextDiagram />

`gh` is a client of the GitHub API only. Other HTTPS Git hosts, such as Bitbucket, are reached by Git
with a personal access token (PAT), never through the GitHub API.

## C2: containers (relationship view)

gh-app-auth is a **single Go binary**. Git or `gh` starts a new process for each invocation, and the
process exits when it is done. There is no daemon.

Installation tokens live in an in-memory cache inside the process: 55 minutes, never written to disk,
and gone when the process exits. Because Git starts a fresh helper per request, the cache mainly helps
processes that stay alive. A background worker removes expired entries; it does not renew them.

## Dynamic flow: Git requests credentials

1. Git matches the remote against its credential configuration and runs the helper with
   `get`, passing `--pattern` for the matching context.
2. The helper reads the host, protocol and path Git sends. With no path it returns empty output. It does
   not rely on Git asking again: `gitconfig --sync` writes `useHttpPath` for path-specific patterns, which
   is what makes Git send the repository path in the first place.
3. It loads the configuration and selects an App and any matching PATs; see
   [how credential routing works](credential-routing.mdx).
4. For an App it signs a JWT, finds or reuses the installation, and exchanges the JWT for an
   installation token, or reuses a cached token. For a PAT it reads the token from the keyring.
5. It prints `username` and `password` to Git. For GitHub the username is `x-access-token`.

## Dynamic flow: exec

1. `exec` selects the credential from the repository or the explicit App selectors.
2. It mints an installation token (or reads the PAT) and builds a child environment from the current
   one: it removes the GitHub token variables, `GH_HOST` and `GH_REPO`, then adds the token, `GH_HOST`
   and, when a repository is known, `GH_REPO`.
3. It runs the child command and returns its exit status. The token is a snapshot: nothing renews it
   during the child's run.
